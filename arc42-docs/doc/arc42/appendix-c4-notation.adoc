== Official C4 Notation Diagram

The C4 model defines four levels of abstraction — Context, Container, Component, and Code — each with a
specific shape, color, and purpose, as defined by Simon Brown. The three levels this documentation
actually models are cross-referenced here rather than repeated: system context in
<<_system_scope_and_context,System Scope and Context>>, containers and components in
<<_building_block_view,Building Block View>>.

The notation legends below show the element types and relationship styles used across this documentation's diagrams.

== Views

[cols="1,2,2,2", options="header"]
|===
|View |Name |Audience |Focus

| *1* | System Context | Non-technical stakeholders | Business scope
| *2* | Container | Technical stakeholders | Technology choices
| *3* | Component | Software architects | Code organization
| *4* | Code | Developers | Implementation details
| *Deployment* | Deployment | DevOps, architects | Infrastructure and runtime topology
| *Dynamic* | Dynamic (Sequence) | Architects, developers | Runtime interaction flows
|===

The *Deployment View* is orthogonal to the four levels of abstraction — it maps containers onto the real
infrastructure nodes (Docker containers, servers) where they run. See <<_deployment_view>>.

The *Dynamic View* traces a specific runtime scenario (e.g. issuing an invoice) across containers and
components.
